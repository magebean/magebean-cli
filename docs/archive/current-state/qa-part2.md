## Actionable cross-rule findings

1. **Potential scope conflict:0072 vs permitted deployment secret storage.** The VCS-history rule also scans the current working tree, with env.php included.0730 deliberately excludes that runtime secret file, and0782 separately enforces absence from the Git index. The executed fixture is chmod0600, has no Git metadata, and still yields a Critical confirmed observed_issue from the working-tree env.php match while0730 PASSes. That is not a Boolean contradiction: scopes intentionally differ. It demonstrates that a VCS-named rule can raise a deployment-secret candidate without any tracked/history exposure being established. Review that applicability and distinguish allowed current local secret storage from historical leakage.
2. **Exact duplicate0728/0731.** Same check name, min_length8, target scope and observation. No built-in currently selects0731, so current built-in counts are not inflated, but users selecting both IDs get duplicate current requirements.
3. **Native/API policies must not be presented as proven vulnerabilities.**0788/0789/0790/0792/0793/0794 are forbidden-API coding policies. The risk projector sets generic failed verified predicates to observed_issue and confirmed (`MagebeanRiskObservation.php:45–51`), without a policy category. The normal CLI overview hides confidence/category (`FindingsConsoleRenderer.php:87`), so the distinction is lost to a user assembling a takeover scope. Confirmed syntax is not confirmed security impact.
4. **Exact operation overlap0788/0792.** The same fixed local file_get_contents triggers both network and filesystem bans in hardening/owasp. These two rules require the explicit strict_native_api_policy capability and do not run by default. When opted in, count/group the operation once; this is neither evidence of SSRF nor path traversal by itself.
5. **Query-builder remediation does not satisfy0786.** The rule admits only a static first string; passing an approved Select/query-builder object through a variable produces UNKNOWN. The remediation explicitly recommends approved query builders. This is an actionable contract mismatch, not proof that query builders are unsafe.
6. **Valuable restored context checks remain unselected.**0733/0736 cover actual bounded development output syntax but have no built-in profile. Meanwhile medium native API bans0789/0790/0791/0793 remain in development/prelaunch/takeover. The low strict-network/filesystem/PRNG policies0788/0792/0794 and literal-query0786 are already capability-gated and must not be described as default findings. That allocation favors coding convention over more contextual source evidence. Add coverage deliberately with overlap grouping, rather than blindly restoring every ID to all profiles.
7. **Subset overlap is not a contradiction.**0038 contains0741's no-file predicate and adds stronger backend constraints;0061 contains0744's strict library-abandonment predicate.0729's absence-of-enabled-declarations policy and0739/0740/0742's requirement for explicit Off can disagree without logical inconsistency because their evidence/absence semantics differ. Share evidence and expose scope, not artificial multiple defects.
