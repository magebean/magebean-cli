# Retirement evidence — middle20 Magebean criteria

Scope: archive positions20–39 (zero based), MB-0077 through MB-0099 with reserved gaps. This review examines the actual registered handlers and current active criteria. The archive's `human_evidence`, `coverage`, and `reason` labels are not used as proof that automation is impossible or that retirement was correct.

## Executed evidence

Run from the CLI repository:

```bash
php tools/verify-retirement-middle20.php
php tools/verify-retirement-middle20.php --json
```

The checked-in probe contains all40 exact fixtures and invokes each archived binding through `CheckRegistry::run()` with its archived arguments. It creates isolated temporary projects, reads inert source/text fixtures, and cleans them up. It does not execute fixture application code or contact the placeholder external endpoints. Two fixtures create real synthetic in-memory SQLite rows with a test PAN/API-key value and expose that PDO through Context. These prove that the legacy source handler ignores those supplied database contents, not that a live Magento MySQL estate was audited.

`PASS` and `FAIL` in the table are raw legacy handler observations. Archived criteria cannot currently be selected as active primary requirements; these probes do not claim current profiles silently run retired rules. The script asserts the observed pairs as evidence anchors; if implementation changes, review and update the evidence instead of preserving a defect.

Persisted machine-readable outcomes: [retirement-evidence-part2-probes.json](retirement-evidence-part2-probes.json). Exact fixture sources and invocation logic: [verify-retirement-middle20.php](../../../tools/verify-retirement-middle20.php).

All20 criteria received two direct execution probes.19 yielded FAIL for an obvious supported signal and PASS for a counterexample; MB-0078 yielded PASS for both strong repository TLS configuration and the same configuration accompanied by a weak second file.

## Review conclusion

The implementation evidence supports retiring or narrowing the **broad assertions**, because the existing handlers can PASS from unrelated markers or unobserved scope. It does **not** support the claim that these20 topics cannot be automated. Every one already has executable collection/predicate logic; many catch useful concrete signals. Several topics have no equal active replacement after retirement, especially PAN/SAD files/database candidates, raw card collection, script inventory/integrity and monitoring. The appropriate next work is to preserve useful observations with explicit confidence/completeness and bind stronger scoped criteria to evidence, rather than either restoring broad false assurance or treating all retired functionality as inherently manual.
