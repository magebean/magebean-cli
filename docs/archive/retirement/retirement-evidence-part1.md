# Retirement evidence part 1 — first 20 archived Magebean rules

This is an implementation/evidence audit, not an endorsement of the archive metadata. The 20 IDs below are exactly the first 20 archive entries, MB-0004 through MB-0076. `human_evidence`, manual labels and retirement reason fields were not treated as proof.

## Reproduction and observed evidence

Run from the CLI repository:

```bash
php tools/retirement-part1-probes.php
php tests/AutomatedSourcePolicyTest.php
php tests/ScopedSourceFilesystemPolicyTest.php
php tests/ComposerMaintenanceCoverageTest.php
php tests/ComposerWithdrawalCoverageTest.php
php tests/ProviderWebhookSourceTest.php
```

The custom probe invokes each archived check through CheckRegistry directly. Retired rule selection remains unchanged. It uses a temporary synthetic project, no runtime URL, no customer code, and no remote API calls. The firewall case temporarily prepends mock `ufw`/`iptables` executables to PATH inside the probe process and restores PATH afterward; it never changes host firewall rules. The output in [retirement-evidence-part1-results.json](retirement-evidence-part1-results.json) is from an actual run; temporary root paths alone were normalized to `<FIXTURE_ROOT>`.

PASS/FAIL/UNKNOWN below are observed handler results, not conclusions that a project is secure/vulnerable. A missing-lock UNKNOWN is deliberately insufficient evidence for removal. The literal-risk source contains request-driven stream/file operations, eval, move_uploaded_file, rand near passwordResetToken, session_start, a plain HTTP endpoint, a named Webhook::execute, and a POST template without form_key. It is parsed/scanned, never executed.

The five existing scripts above passed respectively **64, 15, 11, 8, and 23 assertions**. Composer maintenance/withdrawal scripts exercise active repository/withdrawal status primitives; they are not fabricated tests of every retired Marketplace/support/KEV handler.

## Result

The runs contradict a blanket explanation that all retired checks were inherently manual. Unix permission policy, supported logrotate declarations and enumerated source API policies have observable machine-verifiable behavior. Conversely, unloaded webserver hints, negated mitigation words, and an incomplete firewall parser demonstrate specific ways broad assurance can be falsely accepted.

Six dependency retirements remain **not proven by this part**: MB-0051, MB-0052, MB-0054, MB-0058, MB-0060, MB-0064. Their missing-input UNKNOWN cases establish collection behavior only. Positive/negative populated feed fixtures and explicit acceptance policies are required before a final keep/replace decision. Retirement policy should preserve supported factual automation and narrowly describe its scope, rather than turn uncertainty into a claim that a whole topic cannot be automated.
